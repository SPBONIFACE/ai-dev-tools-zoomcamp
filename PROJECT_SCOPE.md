# AI Household Chore Manager - Project Scope

## 1. Overview
A lightweight, intelligent shared household chore management web application. The application allows household members to manage recurring and ad-hoc chores, record natural language availability and preferences, and trigger an AI-assisted scheduler to fairly allocate chores.

---

## 2. Core Components & Specifications

| Component | Specification |
| :--- | :--- |
| **Interface** | Lightweight web application with an interactive dashboard displaying active chores, member rotation schedules, and completion statuses. |
| **Core Logic** | AI-assisted smart assignment engine that dynamically allocates chores while respecting member availability, preferences, and fairness. |
| **AI Input** | Free-text natural language notes/prompts (e.g., *"Alice is traveling Thursday to Saturday, Bob prefers cooking over cleaning bathrooms"*). |
| **AI Engine** | Pluggable LLM client (OpenAI / Gemini / Groq) with structured JSON output, paired with a deterministic local mock fallback for offline testing and CI pipelines without requiring API keys. |
| **Backend & Storage** | Python (FastAPI) with SQLite database persistence using SQLModel / SQLAlchemy. |
| **Frontend** | Clean, modern HTML5 + JavaScript + Tailwind CSS dashboard served directly by FastAPI static/templates. |
| **Access Control** | Single-household mode (zero-friction, no password/auth required for homework simplicity). |
| **DevOps & Delivery** | Standard AI/DevOps toolchain including `Dockerfile`, `docker-compose.yml`, `Makefile`, and GitHub Actions CI workflow (linting, automated tests, Docker build verification). |

---

## 3. Data Entities

1. **Household Member**
   - `id`: Unique identifier
   - `name`: Member's display name
   - `created_at`: Timestamp

2. **Chore**
   - `id`: Unique identifier
   - `title`: Short task name (e.g., "Clean Kitchen", "Take out Trash")
   - `description`: Details or instructions
   - `frequency`: Recurrence interval (e.g., Daily, Weekly, Bi-weekly, As-needed)
   - `effort_level`: Estimated effort (e.g., 1-5 or Low / Medium / High)
   - `due_date`: Target completion date

3. **Chore Assignment / History**
   - `id`: Unique identifier
   - `chore_id`: Reference to Chore
   - `member_id`: Assigned member
   - `assigned_date`: Date assigned
   - `status`: Pending / In Progress / Completed
   - `completed_at`: Completion timestamp
   - `assignment_reason`: Explanation generated by the AI / allocation engine

---

## 4. Primary User Workflows

1. **View Dashboard**: Inspect weekly/daily chores, who is assigned, and mark chores as completed.
2. **Manage Chores & Members**: Add or edit household members and chores.
3. **Smart Allocation Run**:
   - Provide a natural language prompt or update notes (e.g., vacations, busy days, preferences).
   - Trigger AI allocation.
   - Preview proposed assignments and reasoning, then confirm to apply to the schedule.

---

## 5. DevOps & Quality Architecture

- **Linting & Formatting**: `ruff` or `flake8` + `black`
- **Testing**: `pytest` for unit and integration tests (using the mock AI provider to run keyless in CI)
- **Containerization**: Multi-stage `Dockerfile` + `docker-compose.yml` for local execution and deployment
- **Automation**: `Makefile` providing standard targets (`make install`, `make test`, `make lint`, `make run`, `make docker-build`)
- **CI Pipeline**: GitHub Actions workflow (`.github/workflows/ci.yml`) testing on push and pull requests
